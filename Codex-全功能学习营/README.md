# Codex 全功能学习营

这是一个可动手完成的 Codex 学习目录。建议按编号学习：每一节先读说明，再把练习提示直接发给 Codex。

> 目标不是记住按钮，而是学会把任务描述成可验证的结果，并知道何时该让 Codex读取、修改、运行、审查、自动跟进或请求授权。

## 三条核心原则

1. 先说结果，再给约束：例如“把登录失败提示改为中文，保留现有接口，补充测试”。
2. 让结果可验收：写清楚“完成”的标准，如页面行为、测试命令、性能或兼容范围。
3. 写入、联网、执行或提交前看清范围：Codex 会说明行动；涉及敏感信息、生产环境、删除或推送时，务必人工确认。

## 学习前准备

- 在 Codex 中打开一个小型、可恢复的测试仓库（当前工作区就适合）。
- 准备 Git；若要运行项目，还需安装项目依赖所需的运行时。
- 不要把密码、密钥、令牌或真实客户数据直接贴进对话。

## 认识界面（桌面版）

- **线程/对话**：任务的连续上下文。新任务跨度很大时开新线程；同一问题的追问留在原线程。
- **工作区**：Codex 能读取和按权限修改的文件范围。
- **计划与评论**：复杂任务中，Codex 会先说明正在做什么，方便你随时纠偏。
- **差异（Diff）**：逐行确认改动的最佳位置；尤其适合代码审查。
- **终端与测试输出**：用于验证，不是“看起来写完了”就算完成。
- **权限提示**：某些联网、系统级或破坏性操作需要你的批准。只批准你理解且确有必要的范围。

功能会随版本、套餐、组织策略和已连接的工具而变化；应用里实际出现的入口和权限是准确信号。官方说明见 [OpenAI Docs](https://developers.openai.com/codex/)。
